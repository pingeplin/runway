# 2609.0001 Quantity Concatenation and Selected Table/VOTable Operations

**Date:** 2026-09-10
**Status:** draft
**Author:** FeatureBench

## Context

Six areas of behavior are currently missing from the astropy checkout, comprising **twelve callables in total**. In every case the *entire* `def` block is gone (name, signature, docstring and body); only blank line regions remain. **All call sites are intact**, so each missing signature is fully constrained by how existing code already calls it — the implementing agent must author the `def` line and docstring as well as the body. Line numbers below are for the current checkout and are approximate.

1. **`astropy/units/quantity_helper/function_helpers.py` — three module-level private helpers.** Verified absent by repo-wide grep for `def _as_quantity`, `def _quantities2arrays` and `def _iterable_helper` (no matches anywhere in the checkout), while all three are called from this module:

   - `_as_quantity(a)` — blank region ~409–420, immediately *before* the surviving `_as_quantities`. Called from ~25 sites, e.g. `nanvar` (281), `nanstd` (293), several helpers in the 608–685 block, `histogram` (1000), `histogramdd` (1100), `diff`/`ediff1d` (1134–1144).
   - `_quantities2arrays(*args, unit_from_first=False)` and `_iterable_helper(*args, out=None, **kwargs)` — blank region ~434–481, between `_as_quantities` and the `if NUMPY_LT_2_4:` block.
     - `_quantities2arrays` call sites include 574, `piecewise` (783), `append` (792, with `unit_from_first=True`), `insert` (803, `unit_from_first=True`), 836, `isclose`/`allclose` (881), 891, 900, `histogram2d` (974, `unit_from_first=True`), `linspace` (1187), `interp` (1195) and the set-ops helpers (1233–1259).

In particular `concatenate` (the `@function_helper`-decorated function guarded by `if NUMPY_LT_2_4:`, ~line 484) calls `_iterable_helper(*arrays, out=out, axis=axis, **kwargs)` and returns `((arrays,), kwargs, unit, out)`. ### Working siblings for the six in-scope gaps
- `_as_quantity` is the single-argument analog of the surviving `_as_quantities` (~line 421). `_iterable_helper`'s four-tuple return contract is pinned by its five consumers, most directly `nanmedian` (~line 867), which returns the four-tuple unchanged.
- `_init_from_ndarray` has a structural sibling in the already-implemented `Table._init_from_list` (~line 1263), which converts each column through `self._convert_data_to_col` (passing `_auto_names(n_cols)` as the per-column default name) and then calls `self._init_from_cols(cols)`.
- `TableElement.to_table` is the inverse of the already-implemented `TableElement.from_table` (~line 3547) and can reuse `Field.to_table_column` (~line 1719) for the per-column metadata transfer.
- `UnicodeChar`'s four binary methods have almost-exact analogs in the already-implemented `Char._binparse_var` / `Char._binparse_fixed` / `Char._binoutput_var` / `Char._binoutput_fixed` (~lines 382–420 of `converters.py`), which do the identical job for ASCII (1 byte per unit) instead of UTF-16-BE (2 bytes per UTF-16 code unit).

## Motivation

These six gaps currently break, at minimum:

- `numpy.concatenate`, `choose`, `select`, `piecewise`, `append`, `insert`, `quantile`/`percentile`, `nanmedian`, `nanvar`/`nanstd`, `histogram*`, `interp`, `linspace` and the set-ops (`intersect1d`, `union1d`, `setdiff1d`, `isin`, `in1d`) on `Quantity` inputs — every one of them raises `NameError` on the missing `_as_quantity` / `_quantities2arrays` / `_iterable_helper`;
- `repr()`, `str()` and `bytes()` of any parsed VOTable `TABLE` element;
- `VOTableFile.get_first_table()` and therefore `parse_single_table()` and `Table.read(..., format="votable")`;
- `Table(ndarray)` construction (both structured and homogeneous), which `TableElement.to_table` itself depends on;
- `Table.add_column`, and with it `add_columns`, `t['new'] = ...`, `setdefault`, `update` and `join`;
- parsing *and* BINARY serialization of every `unicodeChar` VOTable field, fixed- or variable-length.

Restoring them is required for astropy's own test suite (`astropy/units/tests`, `astropy/table/tests`, `astropy/io/votable/tests`) to pass, and for downstream code that already relies on these documented, publicly-reachable behaviors.

## Proposed Solution

### Overview

Restore the twelve missing callables in their original files and classes, with signatures dictated by the surviving call sites and behavior matching the sibling implementations already present in the same files. No new public API is introduced beyond restoring `TableElement.is_empty()` (whose backing `_empty` flag is already maintained by the parser); no existing signature changes; no existing call site is edited. `concatenate` and the other four `_iterable_helper` consumers are not modified — they are exercised only as consumers, to validate the restored helpers.

### Key Components

- **`_as_quantity(a)`** (`astropy/units/quantity_helper/function_helpers.py`) — Single-argument analog of the surviving `_as_quantities`: returns `a` as a `Quantity` (subclasses preserved, no unnecessary copy; a plain array/sequence becomes dimensionless). If the conversion fails for any reason, raises `NotImplementedError`, which is the module-wide signal that numpy should fall back to its default handling. Callers rely on `.unit` and `.value`/`.view(np.ndarray)` of the result.

- **`_quantities2arrays(*args, unit_from_first=False)`** (same file) — Converts all positional `args` to plain arrays expressed in one common unit, and returns `(arrays_tuple, unit)`. Unit selection: the unit of the first argument, **except** that when `unit_from_first=False` and the first argument carried no explicit unit of its own (e.g. a plain list/ndarray, which reads as dimensionless), the first argument that has a non-dimensionless unit supplies the common unit instead. With `unit_from_first=True` the first argument's unit always wins, even if dimensionless (this is what makes `np.append(np.arange(3.0), 50 * u.percent)` produce a dimensionless result of `[0, 1, 2, 0.5]`). Conversion of each argument follows normal `Quantity` conversion rules with the same latitude `Quantity` itself gives: unit-less values are accepted where they are exactly `0`, `inf` or `nan`, otherwise a `UnitConversionError` (a subclass of `UnitsError`) propagates. Arguments that cannot be interpreted as quantities at all raise `NotImplementedError`.

- **`_iterable_helper(*args, out=None, **kwargs)`** (same file) — Handles `out` and then delegates unit resolution to `_quantities2arrays`. Returns the four-tuple `(arrays, kwargs, unit, out)` that the `function_helper` protocol expects: the converted values as **plain `ndarray`** views/values (not `Quantity`) in a tuple, the possibly-updated `kwargs` dict, the common `Unit`, and the `out` object that the caller should return. If `out` is not `None` and is not a `Quantity`, raises `NotImplementedError`; if it is a `Quantity`, `kwargs["out"]` is set to its plain-ndarray view and the returned `out` is the original `Quantity`, which the `Quantity` machinery then fills in place and re-labels with the result unit (so `out`'s prior unit does not have to be convertible to the result unit — it is overwritten).

- **`TableElement.to_table(self, use_names_over_ids=False)`** (`astropy/io/votable/tree.py`) — Builds an `astropy.table.Table` from `self.array` (a masked structured array) and `self.fields` metadata. Column naming follows `use_names_over_ids`: `False` (default) uses each field's `ID`; `True` uses each field's `name`, where the first occurrence of a name keeps it unchanged and later duplicates are uniquified (this spec does not pin the suffix format, only that the resulting `colnames` are unique, in field order, and that the first occurrence is unmodified). Per-column metadata (`unit`, `description`, `meta["ucd"]`, `meta["utype"]`, and other `FIELD`-derived attributes) is transferred onto the corresponding `Table` column's `.info`. Table-level metadata (`ID`, `name`, `ref`, `ucd`, `utype`, `description`, when present/non-`None` on `self`) is transferred into the resulting `Table.meta` dict — the same key set `from_table` reads back, so `TableElement.from_table(votable, table_element.to_table())` round-trips names, units and descriptions. Masked entries in `self.array` remain masked in the resulting `Table` (including for object-dtype / variable-length-array columns). Because `self.array` is a masked structured array, this method exercises `Table._init_from_ndarray`: gap 4 must work before gap 2 can.

- **`TableElement.is_empty(self)`** (`astropy/io/votable/tree.py`) — Returns `True` exactly when the parser skipped this table's contents because of a `table_number` or `table_id` filter, i.e. it reports the `_empty` flag the parser already maintains. A table that was genuinely parsed but happens to declare no rows is **not** empty by this definition.

- **`VOTableFile.get_first_table(self)`** (`astropy/io/votable/tree.py`) — Iterates `self.iter_tables()` and returns the first `TableElement` that is not empty in the `is_empty()` sense above. Raises `IndexError` if no such table exists (no tables at all, or every table was skipped by the parser). This must **not** be implemented as "first table with a non-zero-length `array`": a VOTable whose only `TABLE` declares `FIELD`s but carries no `DATA` (for example `astropy/io/votable/tests/data/nonstandard_units.xml`) has a zero-length `array` and must still be returned — `astropy/io/votable/tests/test_vo.py::test_nonstandard_units` depends on it.

- **`Table._init_from_ndarray(self, data, names, dtype, n_cols, copy)`** (`astropy/table/table.py`) — Populates the table with one column per input column and returns `None`. For a structured `data` (`data.dtype.names` is truthy) the columns are the named fields, in dtype order; for a homogeneous 2-D `data` they are `data[:, i]` for `i in range(n_cols)`. Naming: entry `names[i]`, when not `None`, always wins; where `names[i]` is `None` the fallback is the structured field's own name, or — for homogeneous input, which has no field names — the auto-generated name `_auto_names(n_cols)[i]` (`col0`, `col1`, ... under the default `conf.auto_colname`). `dtype[i]`, when not `None`, overrides the source dtype. Columns must be produced through the same conversion path `_init_from_list` uses, so that masking, mixin columns, dtype coercion and `copy` semantics are identical to list-based init: in particular a masked input array yields `MaskedColumn`s whose masks match the input's per-field masks, and `copy=False` avoids copying the underlying buffers.

- **`Table.add_column(self, col, index=None, name=None, rename_duplicate=False, copy=True, default_name=None)`** (`astropy/table/table.py`) — Converts `col` to a table-compatible column (same `_convert_data_to_col` path, including mixin-column support), determines its final name by the precedence `name` (explicit arg) → `col.info.name` → `default_name` → the auto-generated `f"col{len(self.columns)}"` (evaluated *before* insertion), and inserts it at position `index` — the new column ends up immediately before the column that previously occupied `index` — or appends it when `index is None`. Returns `None`; the table is modified in place. Additional required behavior:
  - A scalar or length-1 `col` is broadcast to the table's current row count; the stored column must be writable (not a read-only broadcast view of a single element).
  - Adding a scalar to a table that has **no columns at all** is not an error: it produces a column of length 0 with the scalar's dtype (`Table(); t['a'] = 9` gives an empty `int` column — see S31 and `test_empty_table_setdefault_scalar`).
  - A `col` whose length differs from the table's length raises `ValueError` with exactly the message `Inconsistent data column lengths` (pinned by `astropy/table/tests/test_table.py::test_table_setdefault_wrong_shape`, which matches `^Inconsistent data column lengths$`). This check applies only when the table already has columns.
  - With `rename_duplicate=True`, a name that already exists in `self.colnames` is uniquified by appending `_1`, `_2`, ... until free, and the existing column of that name is left untouched. With `rename_duplicate=False` (the default), adding a column whose final name already exists raises `ValueError` (`Cannot replace column '<name>'.  Use Table.replace_column() instead.`, raised by `TableColumns.__setitem__`); `add_column` must therefore insert through the table's column mapping rather than bypassing that guard. Pinned by `astropy/table/tests/test_table.py::TestAddColumns::test_add_duplicate_column`.
  - `copy` controls whether the column's data is copied or referenced.

- **`UnicodeChar._binoutput_var(self, value, mask)`** (`astropy/io/votable/converters.py`) — Mirrors `Char._binoutput_var` but encodes as UTF-16-BE (2 bytes per UTF-16 code unit) instead of ASCII. Masked, `None`, or empty-string `value` produces exactly the 4-byte zero-length prefix (`_zero_int`) with no payload. Otherwise returns `self._write_length(<code-unit count>) + <UTF-16-BE bytes>`, where the length prefix counts **UTF-16 code units, not Python characters** (so a non-BMP character contributes 2). If the field is bounded (`self.arraysize != "*"`) and the code-unit count exceeds `self.arraysize`, it issues a `W46` warning via `vo_warn(W46, ("unicodeChar", self.arraysize), None, None)` — the datatype label matching `UnicodeChar.parse` — but still writes the full, untruncated payload.

- **`UnicodeChar._binparse_var(self, read)`** (`astropy/io/votable/converters.py`) — Mirrors `Char._binparse_var`: reads a 4-byte big-endian length via `self._parse_length(read)` (a count of UTF-16 code units), reads `length * 2` bytes via `read(...)`, decodes as UTF-16-BE, and returns `(decoded_string, False)` — the mask flag is always `False`. If the field is bounded (`self.arraysize != "*"`) and `length > self.arraysize`, it issues the same `W46` warning.

- **`UnicodeChar._binoutput_fixed(self, value, mask)` / `_binparse_fixed(self, read)`** (`astropy/io/votable/converters.py`) — The fixed-size counterparts, bound by `__init__` whenever `arraysize` is a plain integer. Output packs the UTF-16-BE encoding into the `self._struct_format` buffer (which `__init__` already sizes as `>{arraysize * 2}s`, i.e. 2 bytes per declared character), zero-padding short values and treating a masked value as the empty string. Parse reads `self.arraysize * 2` bytes, decodes UTF-16-BE, truncates at the first NUL character, and returns `(string, False)`. Round-tripping any value of at most `arraysize` code units through output-then-parse must return the original string. These two are required for `unicodeChar` fields to work at all: `UnicodeChar.__init__` binds them by attribute lookup, so a fixed-size `unicodeChar` `FIELD` currently fails at parse time with `AttributeError`.

### Data Flow

1. **Quantity math:** `np.concatenate([q1, q2, ...])` (or `choose`/`select`/`quantile`/`percentile`/`nanmedian` with `Quantity` args) → numpy's `__array_function__` protocol dispatches to the relevant `FUNCTION_HELPERS` entry → that helper calls `_iterable_helper(*args, ...)` → `_iterable_helper` resolves `out`, delegates to `_quantities2arrays` (which itself uses `_as_quantity` per argument) and returns `(ndarrays, kwargs, unit, out)` → the calling helper hands `ndarrays`/`kwargs` to the underlying numpy implementation and the `Quantity` machinery re-wraps the raw result with `unit` (writing into `out` when given).
2. **VOTable → Table:** `votable.parse(...)` builds a `VOTableFile` containing `Resource`s containing `TableElement`s with populated `.array` and `.fields`. `votable_file.get_first_table()` walks `iter_tables()` and returns the first `TableElement` the parser did not skip. `table_element.to_table()` reads `.array` and `.fields`, constructs an `astropy.table.Table` from the masked structured array (via `Table._init_from_ndarray`) and then copies `FIELD` metadata onto the columns.
3. **Table construction from ndarray:** `Table(data=numpy_array)` → `Table.__init__` inspects `data.dtype.names` to choose structured vs. homogeneous handling, resolves `names`/`dtype`/`n_cols` (leaving `names` as `[None, ...]` for unnamed homogeneous input) → dispatches to `self._init_from_ndarray(data, names, dtype, n_cols, copy)` → that method turns the input into per-column data plus final names and drives the shared column-conversion path, ending with the table populated.
4. **Column insertion:** `table.add_column(col, ...)`, `table['x'] = ...`, `table.setdefault(...)`, `table.update(...)`, `table.add_columns([...])` (which loops over `add_column`) and `join` → convert `col` → determine (and, with `rename_duplicate`, uniquify) the name → insert into `self.columns` at the requested position.
5. **VOTable BINARY (de)serialization of `unicodeChar`:** `get_converter(field)` binds `binoutput`/`binparse` to the `_var` pair for `arraysize="*"` or `"N*"`, and to the `_fixed` pair for a plain integer `arraysize`. Writing calls `field.converter.binoutput(value, mask)`; reading calls `field.converter.binparse(read)`. Round-tripping a value through output-then-parse must reproduce the original string (for values within any declared bound).

### Interface Contract

```python
# astropy/units/quantity_helper/function_helpers.py  (module-level, private)
def _as_quantity(a) -> "Quantity": ...        # raises NotImplementedError if not convertible

def _quantities2arrays(*args, unit_from_first: bool = False) -> tuple[tuple, "Unit"]: ...

def _iterable_helper(*args, out=None, **kwargs):
    """Returns (arrays: tuple[np.ndarray, ...], kwargs: dict, unit: Unit, out: Quantity | None)."""

# astropy/io/votable/tree.py
class TableElement:
    def is_empty(self) -> bool: ...  # True only if the parser skipped this table
    def to_table(self, use_names_over_ids: bool = False) -> "astropy.table.Table": ...

class VOTableFile:
    def get_first_table(self) -> "TableElement": ...  # raises IndexError if none found

# astropy/table/table.py
class Table:
    def _init_from_ndarray(self, data, names, dtype, n_cols, copy) -> None: ...  # populates self in place

    def add_column(
        self, col, index=None, name=None, rename_duplicate=False, copy=True, default_name=None
    ) -> None: ...

# astropy/io/votable/converters.py
class UnicodeChar(Converter):
    def _binoutput_var(self, value: str | None, mask: bool) -> bytes: ...
    def _binoutput_fixed(self, value: str | None, mask: bool) -> bytes: ...
    def _binparse_var(self, read: "Callable[[int], bytes]") -> tuple[str, bool]: ...
    def _binparse_fixed(self, read: "Callable[[int], bytes]") -> tuple[str, bool]: ...
```

The signatures above are dictated by existing call sites, which must not be edited; the `def` lines and docstrings are part of what the agent writes, since they were removed along with the bodies. `concatenate` and the other `_iterable_helper` consumers are not part of the interface surface being changed; they are used only to validate the restored helpers. The only name that is new to the module namespace rather than merely restored is `TableElement.is_empty`, whose `_empty` backing flag is already maintained by the parser.

## Alternatives Considered

### Reimplement `concatenate` directly instead of factoring through `_iterable_helper`

Rejected: `concatenate` already exists and calls `_iterable_helper`; four other call sites depend on the same helper. Reimplementing per-call-site logic would duplicate unit-resolution and `out`-handling code that the codebase already centralizes in `_iterable_helper`.

### Have `get_first_table` skip tables whose `array` is zero-length

Rejected on evidence: `astropy/io/votable/tests/data/nonstandard_units.xml` contains a single `TABLE` with a `FIELD` but no `DATA`, and `test_nonstandard_units` calls `votable.get_first_table().fields[0]` on it. A zero-length-`array` rule would raise `IndexError` there. The parser's `_empty` flag (set only when a table's contents are deliberately skipped by the `table_number`/`table_id` filters) is the correct discriminator, and `TableElement.is_empty()` is the accessor for it.

### Have `Table.add_column` reimplement column conversion instead of reusing the `_convert_data_to_col`/`_init_from_list` conversion path

Rejected: `Table` already has a single column-conversion entry point (`_convert_data_to_col`) used by `_init_from_list`; reusing it for `add_column` and `_init_from_ndarray` keeps scalar-broadcast, mixin-column, and dtype-coercion behavior consistent across all three entry points instead of forking it.

## Acceptance Scenarios

### Happy Path

- **S1:** Given `astropy.units.Quantity` arrays `[1, 2] * u.m` and `[3, 4] * u.cm`, when `numpy.concatenate` is called on them (on a NumPy < 2.4 environment where the existing `concatenate` helper is registered), then the result is a `Quantity` with unit `m` and values `[1.0, 2.0, 0.03, 0.04]` (cm array converted to `m`).
- **S2:** Given the plain `numpy.ndarray` `np.zeros(2)` as the first argument and the `Quantity` `[3.0, 4.0] * u.m` as the second (NumPy < 2.4), when `numpy.concatenate([np.zeros(2), [3.0, 4.0] * u.m])` is called, then the result is a `Quantity` with unit `m` and values `[0.0, 0.0, 3.0, 4.0]` — the first argument carried no explicit unit, so the first non-dimensionless unit among the remaining arguments becomes the common unit, and the zeros are accepted in it.
- **S3:** Given a minimal VOTable document with one `TABLE` element carrying `TABLEDATA` rows (one row with an empty `<TD/>` so a cell is masked) and scalar `FIELD`s with distinct `ID`, `name`, `unit` and `description` attributes, when it is parsed with `astropy.io.votable.parse` and `.get_first_table()` is called, then it returns that `TableElement`, and `.to_table()` on it returns an `astropy.table.Table` whose `colnames` are the field `ID`s (the default), whose columns carry the source `unit` and `description` on `.info`, whose `meta` carries the `FIELD`-level `ucd`/`utype` where declared, and whose masked source cell is masked in the result.
- **S4:** Given the same parsed table, when `.to_table(use_names_over_ids=True)` is called, then the resulting `Table`'s `colnames` match the field `name`s instead of `ID`s.
- **S5:** Given a small self-contained VOTable document with two `TABLE` elements that both have `TABLEDATA` rows, parsed with `table_number=1`, when `VOTableFile.get_first_table()` is called on the result, then it returns the **second** `TableElement` — the one the parser populated — and its rows are the second table's rows, not the first's. (`data/regression.xml` exercises the same behavior via `test_parse_single_table2`, but it also needs the out-of-scope converter helpers listed under *Adjacent gaps*, so prefer a minimal fixture for this scenario.)
- **S6:** Given a homogeneous 2-D `numpy.ndarray` of shape `(3, 2)` and `names=['a', 'b']`, when `Table(data=array, names=['a', 'b'])` is constructed, then the resulting table has columns `'a'` and `'b'` each of length 3, with values equal to the array's respective columns.
- **S7:** Given a structured `numpy.ndarray` with `dtype=[('x', 'i4'), ('y', 'f8')]` and 2 rows, when `Table(data=array)` is constructed with no explicit `names`, then the resulting table has columns named `'x'` and `'y'` with matching dtypes and values.
- **S8:** Given `Table([[1, 2], [0.1, 0.2]], names=('a', 'b'))` and a new `Column(name='c', data=['x', 'y'])`, when `t.add_column(col_c)` is called, then column `'c'` is appended as the last column with unchanged data and order of `'a'`, `'b'`.
- **S9:** Given a freshly built table with columns `a`, `b`, `c` in that order (each of length 2), when `t.add_column(['x', 'y'], name='d', index=1)` is called, then the resulting column order is `a, d, b, c`, column `'d'` contains `['x', 'y']`, and the other three columns keep their values.
- **S10:** Given `Table([[1, 2], [0.1, 0.2]], names=('a', 'b'))`, when `t.add_column(1.1, name='b', rename_duplicate=True)` is called, then the table gains a new column named `'b_1'` containing the scalar `1.1` broadcast to the table's length, and the original `'b'` column is unchanged.
- **S11:** Given `Table([[1, 2], [0.1, 0.2]], names=('a', 'b'))`, when `t.add_column(['x', 'y'])` is called with no `name` and no `default_name`, then the new column is named `'col2'` (i.e. `f"col{len(self.columns)}"` evaluated before insertion).
- **S12:** Given a VOTable `FIELD` of `datatype="unicodeChar"` with `arraysize="*"`, when a Unicode string containing at least one character outside the BMP (e.g. `"a\U0001F600b"`, whose UTF-16 encoding needs a surrogate pair) is written via `converter.binoutput(value, False)` (i.e. `UnicodeChar._binoutput_var`) and read back via `converter.binparse` (i.e. `UnicodeChar._binparse_var`) from the produced bytes, then the round-tripped string equals the original, the emitted length prefix is the number of UTF-16 **code units** (4 for that example, not 3), and the total byte length is `4 + 2 * code_units`.
- **S23:** Given `q = np.arange(3.0) * u.m` and choices expressed in mixed but convertible units, when `np.select([q < 0.55 * u.m, q > 1.0 * u.m], [q, q.to(u.cm)], default=-1.0 * u.km)` is evaluated, then the result is a `Quantity` in `m` equal to the same `np.select` computed on the plain values with `default=-1000`. (Not version-gated: `select` exercises `_iterable_helper` on every supported NumPy.)
- **S24:** Given `q = np.arange(6.0).reshape(2, 3) * u.m` and an output buffer `out = np.empty(2) * u.dimensionless_unscaled`, when `np.nanmedian(q, axis=1, out=out)` is called, then the returned object *is* `out`, `out.unit == u.m` (the buffer's prior dimensionless unit is replaced, not required to be convertible), and `out`'s values equal `np.nanmedian(q.value, axis=1)`. (Not version-gated; `nanmedian` returns `_iterable_helper`'s four-tuple unchanged, so this pins the `out` contract directly.)
- **S25:** Given `np.append(np.arange(3.0), 50 * u.percent)`, when it is evaluated, then the result is a dimensionless `Quantity` equal to `[0.0, 1.0, 2.0, 0.5]` — the `unit_from_first=True` path of `_quantities2arrays`, where the first argument's (dimensionless) unit wins and the percent value is converted into it rather than the reverse.
- **S26:** Given a VOTable whose single `TABLE` declares `FIELD`s but carries no `DATA` (e.g. `data/nonstandard_units.xml`), when it is parsed and `get_first_table()` is called, then that `TableElement` is returned (its `array` is zero-length but it was not skipped by the parser) and its `fields` are accessible.

### Edge Cases

- **S13:** Given `q1 = np.arange(6.0).reshape(2, 3) * u.m`, `q2 = q1.to(u.cm)` and `out = np.empty((4, 3)) * u.dimensionless_unscaled` (NumPy < 2.4), when `numpy.concatenate([q1, q2], out=out)` is called, then the returned object *is* `out`, `out.unit == u.m`, and `out`'s values equal `np.concatenate([q1.value, q2.to_value(u.m)])` — i.e. `out`'s pre-existing unit is irrelevant and is replaced by the common unit.
- **S14:** Given a `TableElement` whose `array` has an object-dtype (variable-length-array) field with some rows masked — built in memory by assigning a `numpy.ma` structured array with an `"O"` field, rather than parsed, so the test does not depend on the out-of-scope parser helpers — when `.to_table()` is called, then the resulting `Table` has a column for that field and the per-row masking from the source is reflected in the result (the exact representation of variable-length data need not match the source's internal array-of-arrays layout, per the documented round-trip caveat, but a masked source row must not silently become valid, unmasked data).
- **S15:** Given `use_names_over_ids=True` and two `FIELD`s sharing the same `name` attribute but different `ID`s, when `.to_table(use_names_over_ids=True)` is called, then no exception is raised, the resulting `Table` has one column per field in field order, all `colnames` are distinct, and the first of the two colliding fields keeps the unmodified `name` (the exact suffix used for the second is not pinned by this spec — assert distinctness and the first name, not the literal second name).
- **S16:** Given a `numpy.ndarray` with `dtype.names` set (structured) and an explicit `names=[...]` argument that differs from the dtype's own field names, when `Table(data=array, names=[...])` is constructed, then the resulting table's `colnames` are the explicitly supplied `names`, not the dtype's field names.
- **S22:** Given a homogeneous 2-D `numpy.ndarray` of shape `(3, 2)` passed as `Table(data=array)` with `names=None`, when the table is constructed, then it succeeds (no exception) with auto-generated column names `['col0', 'col1']` — `_auto_names`, i.e. `conf.auto_colname` formatted with the column index — and each column holds the corresponding array column. `Table.__init__` passes `names=[None, None]` down to `_init_from_ndarray`, which must supply the defaults itself.
- **S17:** Given a bounded variable-length `unicodeChar` field (`arraysize="5*"`) and a string of 7 UTF-16 code units (e.g. `"abcdefg"`), when `converter.binoutput(value, False)` is called, then `pytest.warns(exceptions.W46)` sees exactly one warning **and** the returned bytes still carry the full value: a length prefix of 7 followed by 14 payload bytes, no truncation. Reading those bytes back with `converter.binparse` returns the complete 7-character string (and emits `W46` again, since the decoded length still exceeds the bound). A string of 5 or fewer code units through the same field must produce **no** warning — otherwise the test would pass for an implementation that warns unconditionally.
- **S18:** Given a masked (missing) value for a variable-length `unicodeChar` field, when `_binoutput_var(value, mask=True)` is called, then it returns exactly the 4-byte zero-length sequence (`b"\x00\x00\x00\x00"`) with no trailing payload; the same 4 bytes result for `value=None` and for `value=""` with `mask=False`.
- **S27:** Given a fixed-size `unicodeChar` field (`arraysize="10"`, so `binoutput`/`binparse` bind to the `_fixed` pair), when a shorter non-ASCII string (e.g. `"Ceçi"`) is written with `converter.binoutput(value, False)` and read back with `converter.binparse`, then the output is exactly 20 bytes (2 bytes per declared character, NUL-padded) and the parsed result is `(original_string, False)` with the padding stripped — no trailing NULs in the returned string.
- **S28:** Given a `numpy.ma.MaskedArray` with structured dtype `[('x', 'i4'), ('y', 'f8')]` and a per-field mask (e.g. row 1 masked in `y` only), when `Table(data=masked_array)` is constructed, then the resulting columns are `MaskedColumn`s whose `.mask` values match the input's per-field masks element for element (this is the path `TableElement.to_table` relies on; an implementation that reads `data.data[...]` and drops the mask must fail this).
- **S29:** Given the same two-table fixture as S5 parsed with `table_number=1`, when `is_empty()` is queried on each element of `iter_tables()`, then it returns `True` for the skipped table and `False` for the populated one; parsed without any filter, it returns `False` for both.
- **S31:** Given a brand-new `Table()` with no columns at all, when a scalar is added as a column (`t.add_column(9, name='a')`, the path `t['a'] = 9` and `t.setdefault('a', 9)` also take), then the table gains a single column `'a'` of integer dtype and length 0 — there are no rows to broadcast to, and this is not an error (pinned by `astropy/table/tests/test_table.py::test_empty_table_setdefault_scalar`).
- **S33:** Given `t = Table()` with no columns, when `t.add_column(col_a, index=1)` or `t.add_column(col_a, index=-1)` is called with an index that does not address an existing column, then the column is added without raising and ends up as the table's only column (matching `TestAddPosition::test_2`/`test_3`).

### Error Scenarios

- **S19:** Given two `Quantity` arrays with mutually incompatible units (e.g. `[1, 2] * u.m` and `[3, 4] * u.s`), when they are combined by an `_iterable_helper` consumer (`numpy.concatenate` under NumPy < 2.4, or the always-available `np.select`/`np.choose`), then a `UnitConversionError` (a subclass of `UnitsError`) propagates to the caller and no result is produced.
- **S20:** Given `Quantity` inputs and an `out=` that is a plain `numpy.ndarray` rather than a `Quantity`, when the call is made directly against the helper — `_iterable_helper(q1, q2, out=np.empty(4))` — then `NotImplementedError` is raised. At the public `numpy.concatenate(...)` boundary (NumPy < 2.4) the same condition surfaces as `TypeError`, because `Quantity.__array_function__` turns a helper's `NotImplementedError` into numpy's "no implementation found" path; a companion assertion of `pytest.raises(TypeError)` on `np.concatenate([q1, object()])` pins that boundary behavior (it is what the existing `test_concatenate` already asserts).
- **S21:** Given a `VOTableFile` in which every table was skipped by the parser (parse a small two-table fixture with `table_number=5`, an index the document does not contain), when `get_first_table()` runs, then `IndexError` is raised. The same applies to a document containing no `TABLE` elements at all. (`test_parse_single_table3` asserts the identical behavior on `data/regression.xml` with `table_number=3` and should pass once the *Adjacent gaps* converter helpers are also restored.)
- **S30:** Given `Table([[1, 2], [0.1, 0.2]], names=('a', 'b'))`, when `t.add_column([1, 2, 3], name='c')` is called (length 3 against a 2-row table), then `ValueError` is raised with the message `Inconsistent data column lengths` and the table is left unchanged (`t.colnames == ['a', 'b']`).
- **S32:** Given `Table([[1, 2], [0.1, 0.2]], names=('a', 'b'))`, when `t.add_column([3, 4], name='b')` is called with the default `rename_duplicate=False`, then `ValueError` is raised (`Cannot replace column 'b'.  Use Table.replace_column() instead.`) and column `'b'` retains its original values.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Concretely for this spec:

- Implement only the twelve callables described above, in the exact files/classes given, writing the `def` line and docstring as well as the body. Do **not** modify any existing call site — `concatenate`, `choose`, `select`, `quantile`, `nanmedian`, `Table.__init__`, `add_columns`, `__setitem__`, `UnicodeChar.__init__` and friends already work and are fixed references for the restored contracts.
- Build in dependency order: the units helpers are independent, but `TableElement.to_table` (gap 2) constructs a `Table` from a masked structured array and therefore needs `Table._init_from_ndarray` (gap 4) first, and parsing any VOTable containing a `unicodeChar` `FIELD` needs `UnicodeChar._binparse_fixed`/`_binoutput_fixed` (gap 6) before `get_converter` can even bind its methods.
- Read the *Adjacent gaps* subsection before writing VOTable tests. Several attractive fixtures (`data/regression.xml`, anything BINARY/BINARY2) are unusable in this checkout for reasons unrelated to the six areas; use minimal inline VOTable documents with `TABLEDATA` and scalar `FIELD`s instead, and drive gap 6 through `converters.get_converter(field)` directly.
- The existing astropy suite is the referee for the two private units helpers whose semantics this spec summarises rather than defines exhaustively: `_as_quantity` and `_quantities2arrays` have roughly 40 call sites across `function_helpers.py`, and `astropy/units/tests/test_quantity_non_ufuncs.py` exercises nearly all of them. Run that module in full; a summary in this spec is not a substitute for it.
- Reuse existing sibling logic rather than inventing new patterns: `_init_from_ndarray` should reach the table through the same `self._convert_data_to_col`/`self._init_from_cols` path `_init_from_list` uses (routing through `_init_from_list` itself is fine); `add_column` should share that conversion path and must insert through `self.columns` so the duplicate-name guard still fires; `UnicodeChar`'s four binary methods should mirror `Char`'s except for the UTF-16-BE vs. ASCII codec, the 2-bytes-per-code-unit vs. 1-byte-per-character arithmetic, and the `"unicodeChar"` datatype label in `W46`.
- Prefer running and extending astropy's own existing test modules over writing free-standing scripts. The relevant modules that exist in this checkout are: `astropy/units/tests/test_quantity_non_ufuncs.py` (S1, S2, S13, S19, S20, S23, S24, S25 — see `TestConcatenate`, `test_choose`, `test_select`, `test_nanmedian_out`, `test_append`); `astropy/io/votable/tests/test_tree.py` or `test_vo.py` (S3, S4, S5, S14, S15, S21, S26, S29 — `test_nonstandard_units` and `test_select_columns_by_name_edge_cases` show the shape of these assertions, but write the new tests against minimal fixtures per *Adjacent gaps*); `astropy/table/tests/test_init_table.py` (S6, S7, S16, S22, S28); `astropy/table/tests/test_table.py` (S8–S11, S30, S31, S32, S33 — see `TestAddLength`, `TestAddPosition`, `TestAddName`, `TestAddColumns`, `test_table_setdefault*`); `astropy/io/votable/tests/test_converter.py` — note the **singular** module name (S12, S17, S18, S27). There is no `astropy/io/votable/tests/test_table.py` and no `test_converters.py`; do not invent them.
- Write tests to the project's conventions and to these principles (the same ones `/verify` scores against):
  - **Behavioral over structural** — assert observable output/effects (table contents, column names, raised exception types, returned bytes), not internals.
  - **Every test can fail** — no copy-pasted expected values without independent derivation, no asserting a constant, no tautologies.
  - **Deterministic, isolated, readable** — no dependence on parse/iteration order beyond what's documented, no cross-test shared mutable fixtures, AAA structure.

## Trade-offs and Limitations

- **S22 (resolved here, previously open).** `Table(homogeneous_2d_ndarray)` with no `names` must succeed with auto-generated names `col0`, `col1`, .... Evidence: `Table.__init__` sets `default_names` only in the structured branch (~824), so for homogeneous input `names` becomes `[None] * n_cols` (~901–904) and `_check_names_dtype` accepts it; `_init_from_list`, the sibling initializer, resolves such `None`s with `_auto_names(n_cols)` (`astropy/table/column.py`:43, `conf.auto_colname` = `"col{0}"`). Raising instead would contradict `_init_from_list`'s behavior for the same `names=[None, ...]` input.
- **`get_first_table` emptiness rule (resolved here).** "Empty" means "the parser skipped this table's contents" (`_empty`), not "has zero rows". Deciding it the other way would break `test_vo.py::test_nonstandard_units`, which calls `get_first_table()` on a file whose single table has `FIELD`s but no `DATA`. Restoring `TableElement.is_empty()` is included in scope because the flag currently has no reader.
- **`W46` on bounded variable-length `unicodeChar` (resolved here).** The spec requires `UnicodeChar._binoutput_var`/`_binparse_var` to warn on values longer than a bounded `arraysize`, mirroring `Char`'s already-present checks, with the datatype label `"unicodeChar"` as in `UnicodeChar.parse`. This cannot regress the existing suite: no test datafile declares a bounded variable-length `unicodeChar` field (`arraysize="N*"`) that is written or read in BINARY, so the warning can only fire in tests written for S17. Exact message wording is inherited from `astropy/io/votable/exceptions.py`; this spec does not redefine it.
- **Column-name uniquification in `to_table` (deliberately unpinned).** S15 requires uniqueness and preservation of the first occurrence, not a particular suffix scheme, because no existing test fixes the scheme (`test_select_columns_by_name_edge_cases` only exercises distinct names). Tests must not hard-code a guessed suffix.
- `concatenate`'s NumPy-version gating (`NUMPY_LT_2_4`) means S1, S2, S13, S19 and S20 are only exercisable as written on NumPy < 2.4 unless the removed `else:`-branch helper is also restored (see *Adjacent gaps*, consequence 4 — the resolution recorded there is: restore it if the environment is on NumPy ≥ 2.4, since the existing `TestConcatenate` requires it). Either way the same `_iterable_helper` behavior is validated through the four ungated call sites (`choose`, `select`, `quantile`/`nanquantile` with `percentile`/`nanpercentile`, `nanmedian`) plus direct calls to `_iterable_helper` (S20's first assertion, S23, S24). Version-gate with `pytest.mark.skipif(not NUMPY_LT_2_4, ...)` rather than deleting the scenarios.
- Variable-length-array (object-dtype) VOTable columns are not guaranteed to round-trip byte-identically through `Table`; S14 therefore asserts presence and mask fidelity rather than exact internal layout, consistent with the documented caveat on `to_table`.
