# 2609.0001 VOTable Tree Navigation and Table Conversion

**Date:** 2026-09-18
**Status:** accepted
**Author:** FeatureBench

## Context

`astropy/io/votable/tree.py` implements the object tree that backs
`astropy.io.votable`: `VOTableFile` → `Resource` → `TableElement` →
`Field`/`Param`/`Group`/`Values`, plus cross-reference elements like
`ParamRef` and `FieldRef`. Five public members of this tree have been
removed outright — body *and* docstring — leaving a run of blank lines
where each used to be, while the surrounding class scaffolding and the
`_lookup_by_attr_factory`-generated sibling methods are intact:

- `ParamRef.get_ref` (class at `tree.py:2256`; the `ref` property's
  deleter ends at `tree.py:2308`, followed by a blank gap at
  `tree.py:2309-2320` before the next class).
- `TableElement.to_table` — gap at `tree.py:3497-3545`.
  `TableElement.__repr__` (`tree.py:2550`), `__bytes__`, and `__str__`
  already call `self.to_table()`, and `TableElement.from_table`
  (`tree.py:3547`, immediately below the gap) round-trips column metadata
  back through `Field.from_table_column`, implying the missing `to_table`
  must be its inverse, using `Field.to_table_column` (`tree.py:1719`).
- `VOTableFile.__repr__` (gap at `tree.py:4168-4171`, right after
  `__init__`) and `VOTableFile.get_first_table` (gap at
  `tree.py:4498-4507`, right after `iter_tables`). `VOTableFile.iter_tables`
  (`tree.py:4490`) and `get_table_by_index` (`tree.py:4530`) are intact and
  show the iteration pattern (`for resource in self.resources: yield from
  resource.iter_tables()`).
- `VOTableFile.iter_values` — gap at `tree.py:4577-4584`, immediately
  above `get_values_by_id` (`tree.py:4585`), which is generated by
  `_lookup_by_attr_factory("ID", True, "iter_values", "VALUES", ...)` and
  therefore pins `iter_values` to yielding objects carrying an `ID`
  attribute (i.e. `Values` elements).

`VOTableFile._version_namespace_map` (`tree.py:4292`) and its consumers
(`version` setter at `tree.py:4188`, `to_xml` at `tree.py:4358` and
`tree.py:4464`) are already present and wired correctly — they are not
broken, but must not be altered by this change since two of the new
methods (`__repr__` via table counting, `iter_values` via resource
traversal) sit in the same class and must not disturb version handling.

`ParamRef.get_ref` and `FieldRef.get_ref` (the latter fully intact,
`tree.py:2245`) sit side by side; `FieldRef.get_ref` is the direct model
for `ParamRef.get_ref`.

**Four more members are gone from the same file, and are verified
prerequisites of the five above** — without them, no `Field`, `Param`,
`Info`, `FieldRef`, `ParamRef`, `Group`, or `CooSys` can be constructed,
so none of the five members above can be exercised at all, by parsing or
by direct construction:

- `check_string` and `check_astroyear` — module-level functions (gap at
  `tree.py:294-341`, under the `# ATTRIBUTE CHECKERS` section header,
  immediately before `resolve_id` at `tree.py:342` and `check_ucd` at
  `tree.py:349`). Both are called unconditionally, including
  with `None`, from property setters that run in every affected class's
  `__init__`: `check_string` from `_XtypeProperty.xtype` (`tree.py:434`)
  and `_UtypeProperty.utype` (`tree.py:460`), both of which `Field`
  (`tree.py:1428/1433`), `Info` (`tree.py:810/814`), `FieldRef`
  (`tree.py:2220`), `ParamRef` (`tree.py:2285`), and `Group`
  (`tree.py:2366`) assign in `__init__`; `check_astroyear` from
  `CooSys.equinox`/`epoch` (`tree.py:1981`, `tree.py:1998`). Neither name
  is defined anywhere in the package (`grep -rn "^def check_string\|^def
  check_astroyear" astropy/` finds nothing) nor imported into `tree.py`.
  Confirmed by direct construction: `Field.__init__` unconditionally sets
  `self.utype = utype`, which raises `NameError: name 'check_string' is
  not defined` today, for every `Field`. Both names are also called by
  name in the still-present `astropy/io/votable/tests/test_tree.py:27-37`
  (`tree.check_astroyear(...)`, `tree.check_string(...)`), which imports
  `W07`/`W08` from `exceptions.py` for exactly this purpose — both codes
  are already imported into `tree.py` (`tree.py:49-50`) and otherwise
  unused there, which is why the gap doesn't show up as an import error.
- `CooSys.reference_frames` (gap at `tree.py:1949-1969`, between the
  `system` property/setter and the `equinox` property) — `CooSys.system`'s
  setter reads `self.reference_frames` (`tree.py:1941`) unconditionally.
  `data/regression.xml:10` — the fixture the existing test suite already
  uses for `to_table`/`get_first_table` (`test_table.py:63-73`) — contains
  `<COOSYS ID="J2000" system="eq_FK5" equinox="J2000"/>`, so parsing that
  file constructs a `CooSys` and hits this gap today.
- `TableElement.is_empty` (gap at `tree.py:2706-2713`, between the
  `infos` property and `create_arrays`) — `TableElement._empty` is
  written during parsing (`tree.py:2518` default, set `True` at
  `tree.py:2828`/`tree.py:2834` when a `table_number=`/`table_id=`
  parse option causes this table to be skipped) but never read by
  anything in the file. `get_first_table` needs a way to skip those
  tables (see Key Components below); `is_empty` is the reader the gap's
  size and position match.

Two further gaps exist in the file (`tree.py:1190-1219`, inside `Values`,
between `parse` and `is_defaults`; `tree.py:3671-3674`, inside
`MivotBlock`, before `_add_statement`) but nothing on any acceptance
scenario's execution path calls into either — `Values.__init__`,
`.parse`, `.is_defaults`, `.to_xml`, `.to_table_column`, and
`.from_table_column` are all present and sufficient for `Field`
construction and `to_table`; `MivotBlock.check_content_format`
(`tree.py:3772`) is present, and no fixture used here contains a MIVOT
block. Both are Out of Scope below.

Existing tests in `astropy/io/votable/tests/test_table.py` and
`astropy/io/votable/tests/test_tree.py` already call `get_first_table()`,
`.to_table()`, and `VOTableFile.from_table(...)` throughout (e.g.
`test_table.py:66-73`, `test_table.py:172`, `test_table.py:237`,
`test_table.py:445-448`) — these calls currently fail (`AttributeError`
for the five removed members, or `NameError` earlier still, at the first
`Field`/`Info` construction) so the existing VOTable test suite fails
before it reaches most of its assertions.

## Motivation

`astropy.io.votable`'s primary consumer-facing workflow is "parse a VOTable
file, get an `astropy.table.Table` out of it" (`votable.get_first_table().
to_table()`), and the reverse ("build a VOTable from a Table",
`VOTableFile.from_table(...)`, already implemented). With `to_table`,
`get_first_table`, `iter_values`, `VOTableFile.__repr__`, and
`ParamRef.get_ref` missing — and with the tree unable to construct a
single `Field` without `check_string` — that workflow, and every test
exercising it, is broken. Restoring the five target members plus their
four verified prerequisites brings the tree module's navigation-and-
conversion surface back to a working, testable state without altering the
members that still have bodies (`to_xml` serialization, `from_table`,
`Field.to_table_column`, version/namespace handling).

## Proposed Solution

### Overview

Implement the five target members using the same patterns already present
elsewhere in `tree.py`: `ParamRef.get_ref` mirrors `FieldRef.get_ref`
(linear search over `iter_fields_and_params()`, raising via `vo_raise`);
`TableElement.to_table` mirrors the inverse direction of the already-working
`TableElement.from_table` classmethod, building an `astropy.table.Table`
column-by-column via `Field.to_table_column`; `VOTableFile.get_first_table`
returns the first table the parser actually populated, skipping tables the
parser was told to skip; `VOTableFile.iter_values` walks
`iter_fields_and_params()` yielding each field/param's `.values`;
`VOTableFile.__repr__` summarizes the file by its table count. Alongside
these, restore the four prerequisite members using the same
`warn_or_raise`/config-driven pattern as the intact `check_ucd`
(`tree.py:349`): `check_string`, `check_astroyear`, `CooSys.reference_frames`,
`TableElement.is_empty`.

### Key Components

- **`ParamRef.get_ref`** (`astropy/io/votable/tree.py`, in `ParamRef`,
  filling the gap at lines 2309-2320 after the `ref` property deleter) —
  searches `self._table._votable.iter_fields_and_params()` for a `Param`
  instance whose `ID` equals `self.ref`, returning it. Raises `KeyError`
  (via `vo_raise`, matching `FieldRef.get_ref`'s pattern) when no match
  exists.

- **`TableElement.to_table`** (`astropy/io/votable/tree.py`, in
  `TableElement`, filling the gap at lines 3497-3545 immediately before
  the existing `from_table` classmethod) — builds an
  `astropy.table.Table` from `self.array`, one column per entry of
  `self.fields`, then calls `field.to_table_column(column)` on each
  resulting column to transfer unit/description/ucd/values metadata.
  `self.fields` — not `all_fields` — is the correct column list: when a
  file is parsed with the `columns=` option, `create_arrays`
  (`tree.py:2735-2761`) narrows `self._fields` to the selected columns and
  builds `self.array`'s dtype from exactly that subset, so pairing
  `self.array`'s columns with `all_fields` would misalign. Column names
  come from each field's `ID`, or from each field's `name` when
  `use_names_over_ids=True`; either way, uniqueness is already guaranteed
  by parse time — `Field.uniqify_names` (`tree.py:1440-1473`, called from
  `create_arrays`) rewrites colliding `ID`s into `field.ID` and colliding
  names into `field._unique_name` before `to_table` ever runs, so
  `to_table` reads the already-unique value rather than performing its
  own disambiguation. Copies `ID`, `name`, `ref`, `ucd`, `utype`,
  `description` from the `TableElement` into `table.meta`, omitting any
  of those keys whose attribute is `None`. Per the Interface Description
  (embedded verbatim below), table-level `INFO`/`LINK` elements are not
  copied into `table.meta`.

- **`VOTableFile.get_first_table`** (`astropy/io/votable/tree.py`, in
  `VOTableFile`, filling the gap at lines 4498-4507 after `iter_tables`) —
  returns the first table in `self.iter_tables()` order for which
  `table.is_empty()` is `False`. When `parse()` is given `table_number=`
  or `table_id=`, the tables that do not match are parsed for metadata
  only and flagged (`TableElement._empty`, set at `tree.py:2828` and
  `tree.py:2834`, read via the restored `TableElement.is_empty()`);
  `get_first_table` passes over those. "Empty" here means *skipped by the
  parser*, not *zero-row*: a table that was read and happens to have no
  rows (e.g. `data/regression.xml`'s `last_table`, `<TABLEDATA/>` with no
  `<TR>`) is returned normally when it is the first non-skipped table.
  Raises `IndexError` when no such table exists. `parse_single_table`
  (`table.py:167-184`) depends on this: it forces `table_number=0` and
  then calls `get_first_table()`.

- **`VOTableFile.iter_values`** (`astropy/io/votable/tree.py`, in
  `VOTableFile`, filling the gap at lines 4577-4584 immediately above
  `get_values_by_id`) — for each element yielded by
  `self.iter_fields_and_params()`, yields `element.values`.

- **`VOTableFile.__repr__`** (`astropy/io/votable/tree.py`, in
  `VOTableFile`, filling the gap at lines 4168-4171 after `__init__`) —
  returns `f"<VOTABLE>... {n} tables ...</VOTABLE>"` where `n` is the
  number of tables `iter_tables()` yields (parser-skipped and zero-row
  tables both count).

- **`check_string`** (`astropy/io/votable/tree.py`, module-level function
  alongside `check_ucd`, filling the gap before `tree.py:349`) —
  `check_string(string, attr_name, config=None, pos=None)`. `None` is
  accepted silently (every caller invokes it even when the attribute is
  unset). A `string` that is neither `None` nor a `str`/`bytes` triggers
  the project's `warn_or_raise(W08, ...)` path (warn, raise, or ignore
  per `config.get("verify")`, mirroring `check_ucd`'s existing
  `config.get("verify")` branches). Required so `Field`, `Param`, `Info`,
  `FieldRef`, `ParamRef`, and `Group` can be constructed at all — every
  one of them assigns `xtype` and/or `utype` in `__init__`. Verified
  oracle: `astropy/io/votable/tests/test_tree.py:33-36`
  (`tree.check_string(42, "foo", config)` with `config={"verify":
  "exception"}` must raise `W08`).

- **`check_astroyear`** (`astropy/io/votable/tree.py`, module-level
  function alongside `check_string`) —
  `check_astroyear(year, attr_name, config=None, pos=None)`. `None` is
  accepted silently. A `year` that is neither `None` nor a match for the
  VOTable `astroYear` pattern `^[JB]?[0-9]+([.][0-9]*)?$` (documented on
  `W07`, `exceptions.py:437-452`) triggers `warn_or_raise(W07, ...)`.
  Required so `CooSys.equinox`/`epoch` can be set. Verified oracle:
  `astropy/io/votable/tests/test_tree.py:27-31`
  (`tree.check_astroyear("X2100", field, config)` with
  `config={"verify": "exception"}` must raise `W07`).

- **`CooSys.reference_frames`** (`astropy/io/votable/tree.py`, in
  `CooSys`, filling the gap at lines 1949-1969 between the `system`
  property/setter and the `equinox` property) — exposes, as
  `self.reference_frames`, a collection containing at least the ten
  values documented on `E16` (`exceptions.py:1446-1459`): `'eq_FK4'`,
  `'eq_FK5'`, `'ICRS'`, `'ecl_FK4'`, `'ecl_FK5'`, `'galactic'`,
  `'supergalactic'`, `'xy'`, `'barycentric'`, `'geo_app'`. `system`'s
  setter (`tree.py:1941`) checks membership in this collection and raises
  `E16` on a miss. Scoped narrowly to unblock `CooSys` construction (and
  therefore parsing `data/regression.xml`) — this spec does not require
  matching every nuance of `astropy/io/votable/tests/test_coosys.py`
  (version-gated systems, legacy aliases like `"FK4"`), which is Out of
  Scope.

- **`TableElement.is_empty`** (`astropy/io/votable/tree.py`, in
  `TableElement`, filling the gap at lines 2706-2713 between the `infos`
  property and `create_arrays`) — `def is_empty(self) -> bool: return
  self._empty`. The public reader `get_first_table` uses.

### Data Flow

1. **`to_table` (parse → Table):** `TableElement.array` (already populated
   by the existing parser) + `TableElement.fields` (already populated, and
   column-for-column aligned with `array`) → one `astropy.table.Column`
   per field, columns assembled into an `astropy.table.Table`, each column
   decorated via `Field.to_table_column` → table-level metadata copied
   from the `TableElement`'s own attributes.
2. **`get_first_table`:** `VOTableFile.resources` → `Resource.iter_tables()`
   → `VOTableFile.iter_tables()` (both already implemented; both yield
   *every* table, including parser-skipped ones — neither filters) → first
   table for which `is_empty()` is `False`.
3. **`iter_values`:** `VOTableFile.resources` → `Resource.iter_fields_and_params()`
   (already implemented, covers tables' and the resource's own
   fields/params) → `VOTableFile.iter_fields_and_params()` (already
   implemented) → `.values` attribute of each `Field`/`Param`.
4. **`get_ref`:** `ParamRef._table` (the enclosing `Group`'s table,
   assigned in `Group.__init__`) → `._votable` → `iter_fields_and_params()`
   → filter to `Param` instances whose `.ID == self.ref`.
5. **Construction prerequisite:** any `Field`/`Param`/`Info`/`FieldRef`/
   `ParamRef`/`Group`/`CooSys.__init__` → property setters call
   `check_string`/`check_astroyear`/`self.reference_frames` → must not
   raise `NameError`/`AttributeError` for this to reach step 1-4 at all.

### Interface Contract

The five target members' contracts are fixed by the Interface Description
this spec was written from — embedded verbatim so the implementing agent
does not have to reconstruct them from callers:

```python
# astropy/io/votable/tree.py

class ParamRef(SimpleElement, _UtypeProperty, _UcdProperty):
    def get_ref(self):
        """
        Lookup the :class:`Param` instance that this :class:`ParamRef` references.

        This method searches through all FIELD and PARAM elements in the VOTable
        to find a PARAM element whose ID matches the 'ref' attribute of this
        ParamRef instance.

        Returns
        -------
        param : :class:`Param`
            The Param instance that matches the reference ID.

        Raises
        ------
        KeyError
            If no PARAM element with the specified ID is found in the VOTable.

        Notes
        -----
        All FIELD and PARAM elements in the VOTable are considered, but only a
        matching PARAM element is a valid result. Lookup is not restricted to
        elements appearing before the reference.
        """


class TableElement(Element, _IDProperty, _NameProperty, _UcdProperty, _DescriptionProperty):
    def to_table(self, use_names_over_ids=False):
        """
        Convert this VO Table to an `astropy.table.Table` instance.

        Parameters
        ----------
        use_names_over_ids : bool, optional
           When `True` use the ``name`` attributes of columns as the
           names of columns in the `astropy.table.Table` instance.
           Since names are not guaranteed to be unique, this may cause
           some columns to be renamed by appending numbers to the end.
           Otherwise (default), use the ID attributes as the column
           names.

        Returns
        -------
        table : `astropy.table.Table`
            An astropy Table instance containing the data from this VOTable.
            The table's metadata will include relevant VOTable attributes
            such as ID, name, ref, ucd, utype, and description when present.
            Each field also transfers the column metadata handled by
            `Field.to_table_column`, including units and descriptions.

        Notes
        -----
        Variable-length array fields may not be restored identically when
        round-tripping through the `astropy.table.Table` instance due to
        differences in how astropy.table and VOTable handle such data.

        The conversion process preserves:
        - Column data types and values
        - Column names (either from ID or name attributes)
        - Units and descriptions
        - UCD (Unified Content Descriptor) information

        Table-level INFO and LINK elements are not copied into `table.meta`;
        field-level LINK metadata is transferred by `Field.to_table_column`.
        """


class VOTableFile(Element, _IDProperty, _DescriptionProperty):
    def __repr__(self):
        """
        Return a string representation of the VOTableFile object.

        Returns
        -------
        str
            A string in the format "<VOTABLE>... N tables ...</VOTABLE>" where
            N is the total number of tables across all resources in the file.

        Notes
        -----
        The count includes all tables from all nested resources within the
        VOTable file. Empty tables (those with no data) are included in the
        count.
        """

    def get_first_table(self):
        """
        Get the first table in the VOTable file.

        Returns
        -------
        table : `~astropy.io.votable.tree.TableElement`
            The first non-empty table found in the VOTable file.

        Raises
        ------
        IndexError
            If no non-empty table is found in the VOTable file.

        Notes
        -----
        Tables are considered in document order. Empty tables are those skipped
        during parsing, typically when a table-selection option was used.
        """

    def iter_values(self):
        """
        Recursively iterate over all VALUES_ elements in the VOTABLE_ file.

        Yields
        ------
        Values
            Each VALUES_ element found in the VOTable file, including those
            nested within resources, tables, fields, and parameters.

        Notes
        -----
        VALUES_ elements that have no meaningful constraints (i.e., those for
        which `Values.is_defaults()` returns True) are still included in the
        iteration.
        """
```

`connect.py:128` calls `table.to_table(use_names_over_ids=use_names_over_ids)`;
`table.py:184` and `table/table_helpers.py:97` call `votable.get_first_table()`
with no arguments; `get_values_by_id` (`tree.py:4585`) calls `iter_values()`
with no arguments and reads `.ID` off each yielded element — all three
confirm the signatures above. This spec does not add, remove, or rename
any of these five public members.

The four prerequisite members have no surviving Interface Description
(they are not part of the "exposed VOTable tree operations" this feature
request names); their contracts above are derived from call sites,
`exceptions.py`, and `test_tree.py`'s existing oracle tests, per Key
Components.

## Out of Scope

- Changing how `TableElement.array` is populated during parsing beyond
  what's needed for `Field`/`Param`/`Info`/`FieldRef`/`ParamRef`/`Group`/
  `CooSys` to construct without error — the parser's data-reading logic
  itself (`_parse_tabledata`, `_parse_binary`, etc.) already works and is
  untouched.
- Changing `TableElement.from_table`, `Field.from_table_column`, or
  `Field.to_table_column` — all three already exist and are load-bearing
  prerequisites that `to_table` calls into, not targets of this change.
- Changing `VOTableFile.iter_tables`, `VOTableFile.iter_fields_and_params`,
  `Resource.iter_tables`, or `Resource.iter_fields_and_params` — all four
  already exist and are prerequisites `get_first_table`/`iter_values` call
  into.
- Changing `_version_namespace_map` values, the `version` setter, or
  `to_xml`'s use of the namespace map — already correct; only asserted as
  unchanged by this spec's acceptance scenarios.
- `FieldRef.get_ref` — already fully implemented; used only as a reference
  pattern.
- The `Values` gap at `tree.py:1190-1219` and the `MivotBlock` gap at
  `tree.py:3671-3674` — neither is on the execution path of any scenario
  below (see Context); left untouched.
- Full parity with `astropy/io/votable/tests/test_coosys.py` — version-
  gated `system` values, legacy aliases (e.g. `"FK4"` alongside
  `"eq_FK4"`), and `refposition` handling. `CooSys.reference_frames` is
  restored only far enough to let `data/regression.xml`'s
  `system="eq_FK5"` COOSYS parse without error.
- `parse()`'s `table_id=` argument, which never reaches `config` in
  `table.py:144-153` and is therefore inert even after this change — a
  pre-existing bug, not introduced or fixed here. Scenario S11 below uses
  `table_number=` instead.

## Acceptance Scenarios

Fixture facts these scenarios rely on, verified in the checkout:
`data/regression.xml` has exactly three `<TABLE` elements (`grep -n
"<TABLE\b"`): `main_table` (`ID="main_table"`, 5 `<TR>` rows), an unnamed
table (`ref="main_table"`, 1 row), and `last_table` (`ref="main_table"
ID="last_table"`, `<TABLEDATA/>` — 0 rows, and *not* parser-skipped, since
no `table_number=`/`table_id=` option is used to parse it in these
scenarios). It has one `RESOURCE`-level `PARAM ID="awesome"` (unit
`"deg"`), a `GROUP` inside `main_table` containing `<PARAMref
ref="awesome"/>` (and a second, identical `PARAMref ref="awesome"` in a
second `GROUP`, also inside `main_table`), a `FIELD` with `id="string_test"`
and another with `ID="string_test"` (both inside `main_table`; no `PARAM`
anywhere has that ID), and one `COOSYS ID="J2000" system="eq_FK5"
equinox="J2000"`. `data/empty_table.xml` holds one `TABLE` with fields
`unsignedByte` and `short` and no `DATA`. `data/names.xml` holds one table
whose field IDs are `col1`…`col17` and whose field names are `Name`,
`GLON`, `GLAT`, `RAdeg`, `DEdeg`, `Jmag`, `Hmag`, `Kmag`, `G3.6mag`,
`G4.5mag`, `G5.8mag`, `G8.0mag`, `4.5mag`, `8.0mag`, `Emag`, `24mag`,
`f_Name` (`test_table.py:167-192`, already in the suite).

### Happy Path

- **S1:** Given `parse("data/regression.xml")`, when `get_ref()` is called
  on the `ParamRef` inside `main_table`'s `GROUP` (`ref="awesome"`), then
  it returns the `Param` with `ID == "awesome"` — the same object the
  resource holds (identity), whose `unit` is `deg`.
- **S2:** Given `parse("data/regression.xml").get_first_table()`, when
  `.to_table()` is called, then the result is an `astropy.table.Table`
  whose `colnames` are the table's field IDs in field order and whose
  column values equal `table.array[name]` for every one of those names.
- **S3:** Given the same table as S2, when `.to_table()` is called, then
  for every column name the output's `mask[name]` equals
  `table.array.mask[name]`, so masked cells stay masked.
- **S4:** Given `parse("data/names.xml").get_first_table()`, when
  `.to_table(use_names_over_ids=True)` is called, then `colnames` equals
  `["Name", "GLON", "GLAT", "RAdeg", "DEdeg", "Jmag", "Hmag", "Kmag",
  "G3.6mag", "G4.5mag", "G5.8mag", "G8.0mag", "4.5mag", "8.0mag", "Emag",
  "24mag", "f_Name"]`.
- **S5:** Given the same table as S4, when `.to_table(use_names_over_ids=False)`
  is called, then `colnames` is `["col1", "col2", ..., "col17"]` — the
  fields' `ID` attributes.
- **S6:** Given a `Field` with `unit="mag"`, a description, and
  `ucd="phys.luminosity"`, when its owning `TableElement.to_table()` is
  called, then the matching output column has `column.unit == u.mag`,
  `column.description` equal to the field's description, and
  `column.meta["ucd"] == "phys.luminosity"`.
- **S7:** Given `parse("data/regression.xml").get_first_table()` (which
  has `ID="main_table"` and a `DESCRIPTION`), when `.to_table()` is
  called, then `table.meta["ID"] == "main_table"` and
  `table.meta["description"]` carries the table's description text.
- **S8:** Given `parse("data/regression.xml")`, when `.get_first_table()`
  is called, then the returned `TableElement` has `ID == "main_table"` and
  5 rows in its `array`.
- **S9:** Given a `VOTableFile` with two tables, each holding one `FIELD`
  that carries a `VALUES` element, when `list(votable.iter_values())` is
  called, then the result is exactly the two fields' `.values` objects
  (identity match, in table order).
- **S10:** Given `parse("data/regression.xml")` (three tables, one of them
  the zero-row `last_table`), when `repr(votable)` is called, then the
  result is `"<VOTABLE>... 3 tables ...</VOTABLE>"` — every table counts,
  whether or not it has rows.

### Edge Cases

- **S11:** Given `parse("data/regression.xml", table_number=2)`, where the
  parser reads only the third table (`last_table`) and passes over the two
  ahead of it, when `.get_first_table()` is called, then it returns the
  table with `ID == "last_table"`, not the first table in document order.
- **S12:** Given `parse("data/empty_table.xml")`, whose single table was
  read but contains no rows, when `.get_first_table()` is called, then it
  returns that table (`is_empty()` is `False`) rather than raising — a
  row-less table that the parser actually read is still a table.
- **S13:** Given the table from S12, when `.to_table()` is called, then it
  returns a `Table` with `len(table) == 0` and
  `colnames == ["unsignedByte", "short"]`, raising nothing.
- **S14:** Given `TableElement.from_table(votable, simple_table())`, whose
  source `Table` carries no `meta` and so leaves `ID`, `name`, `ref`,
  `ucd`, and `utype` unset, when `.to_table()` is called, then
  `table.meta` contains none of those five keys.
- **S15:** Given a `TableElement` with two fields whose `name` is `"flux"`
  for both (IDs `col1` and `col2`), when `.to_table(use_names_over_ids=True)`
  is called, then the two `colnames` are distinct: the first is `"flux"`
  and the second is `"flux"` with a number appended (per
  `Field.uniqify_names`, already-run by parse/`create_arrays` time).
- **S16:** Given a `VOTableFile` with zero `TABLE` elements anywhere, when
  `.get_first_table()` is called, then it raises `IndexError`.
- **S17:** Given a `VOTableFile` with no `FIELD` or `PARAM` elements
  anywhere, when `list(votable.iter_values())` is called, then it returns
  `[]`.
- **S18:** Given `t = simple_table()` and the round trip
  `TableElement.from_table(votable, t).to_table()`, when the round-tripped
  table is compared to `t`, then `colnames` and cell values match
  (metadata fidelity is scoped to what `Field.from_table_column` /
  `to_table_column` already preserve — unit, description, ucd).
- **S23:** Given `parse("data/regression.xml")` (which contains `<COOSYS
  ID="J2000" system="eq_FK5" equinox="J2000"/>`), when the file is parsed,
  then no exception is raised and the resulting `CooSys`'s `system` equals
  `"eq_FK5"`.
- **S24:** Given `parse("data/regression.xml")`'s `last_table` (0 rows,
  read normally, not parser-skipped) and a table obtained via
  `parse("data/regression.xml", table_number=0)` (the parser skips
  `main_table`... i.e. any table other than ordinal 0 is skipped), when
  `.is_empty()` is called on each, then `last_table.is_empty()` is
  `False` and the skipped table's `is_empty()` is `True`.

### Error Scenarios

- **S19:** Given a `ParamRef` with `ref="no_such_param"` whose
  `VOTableFile` contains no `Param` with that `ID`, when `.get_ref()` is
  called, then it raises `KeyError`.
- **S20:** Given `parse("data/regression.xml")` (whose only `ID` equal to
  `"string_test"` belongs to a `FIELD`, not a `PARAM`) and a
  `ParamRef(table, ref="string_test")` constructed against that file's
  first table, when `.get_ref()` is called, then it raises `KeyError`
  rather than returning the `Field`.

- **S22:** Given `config = {"verify": "exception"}` and a `Field`

> **Your job:** make every acceptance scenario above pass with tests that
> would *fail if the behavior were wrong*. A green suite that passes for
> the wrong reason does not satisfy this contract — `/verify` will hunt for
> vacuous tests by asking, of each behavior, "what is the smallest change
> that breaks this, and would any test catch it?"

Implement the five target members plus the four prerequisite members
directly in `astropy/io/votable/tree.py` at the locations described in Key
Components — do not relocate existing code, do not change
`_version_namespace_map` or any method that already has a body. Each
target member needs a docstring; use the Interface Contract text verbatim.
Run the existing suite first (`astropy/io/votable/tests/test_table.py`,
`astropy/io/votable/tests/test_tree.py`,
`astropy/io/votable/tests/test_converter.py`,
`astropy/io/votable/tests/test_dataorigin.py`) — much of it already
exercises these members and will go from failing to passing once they're
implemented; treat newly-passing existing tests (including
`test_tree.py:27-36`, which already tests `check_astroyear`/`check_string`
by name) as primary evidence alongside any new tests you add for the
scenarios above. Write tests to the project's conventions (pytest,
`astropy/io/votable/tests/`, using `get_pkg_data_filename` for fixture
files) and to these principles (the same ones `/verify` scores against —
see `references/test-desiderata.md` and `references/anti-patterns.md`):

- **Behavioral over structural** — assert observable output/effects
  (column names, values, masks, repr strings, raised exceptions), not
  internals; the suite must survive refactoring.
- **Every test can fail** — no copy-pasted expected values, no asserting a
  constant, no tautologies (AP-2, AP-4).
- **Deterministic, isolated, readable** — build VOTable trees explicitly
  in each test (or via existing `data/*.xml` fixtures) rather than relying
  on shared mutable module state; AAA structure with inline setup.

Parsing `data/regression.xml` overflows on purpose (astropy issue 13341);
wrap those calls in `with np.errstate(over="ignore"):` as
`test_table.py:63-65` does, or the scenario fails on a warning rather than
on its behavior.

## Trade-offs and Limitations

- Variable-length array fields may not round-trip identically through
  `to_table`/`from_table` — a pre-existing limitation of the
  astropy.table/VOTable type mapping (visible in `Field.to_table_column`'s
  handling of `arraysize="*"` columns), not something this change is
  expected to fix. S18's round-trip scenario is therefore stated over a
  simple fixed-width table.
- `iter_values` yields every `Values` element reached via fields/params,
  including ones for which `Values.is_defaults()` is `True` (no
  constraints set); filtering is the caller's job. `get_values_by_id`
  (`tree.py:4585`) relies on this unfiltered stream to find a `VALUES`
  element by ID.
- `CooSys.reference_frames` is restored to the minimum needed to parse
  `data/regression.xml`'s COOSYS (the ten values `E16` documents); it does
  not attempt version-gating or legacy-alias behavior that
  `test_coosys.py` alone would require, since no scenario here needs it.
- `check_string`/`check_astroyear` are restored to the minimum behavior
  the existing `test_tree.py` oracle requires (reject non-`str`/non-match
  values via `W08`/`W07`, accept `None`); any richer validation
  `test_coosys.py`/other suites might expect is not covered here.
